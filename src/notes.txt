  * Worker Death:
    * Currently there are a few ways a worker can fail, and in
      most cases, the worker will be able to communicate the
      error back to the builder:
      - The preprocess or compile command returns an error code.
         => this will be cleanly returned via redis.
      - The preprocess or compile command times out.
         => this will be cleanly returned via redis.
      - A lua exception happens when processing the task.
         => Most of the relevant code is wrapped in a pcall
            and the worker will communicate an error via
            redis before exiting.
      - The node manager can SIGTERM the worker.
         => When this happens, if there is a task running, then
            the associated subprocess will also receive the
            signal (via process group) and it will terminate
            with an error code that will be propagated.
      - The worker can suddenly disappear after having taken a
        a task, for unknown reasons.
         => Not handled.
      The last case is not handled, but it doesn't ever seem to

      vertised, then reclaim that task. It would then increment a
      failure counter for that ask, and, assuming retries haven't
      been exceeded, it can put it back onto the front of the
      global queue so it gets retried. But that seems like it is
      not worth the effort since this doesn't seem to happen.

Plan for Cluster Manager:
-----------------------------------------------------------------
  * Jobs run by Cluster Manager:
    - Redis Database (?) - not sure yet.
    - Distributor
    - Power Meter: will determine the power of each node and up-
      load it as a sorted set to Redis for consumption by the
      Distributor.
    - Node Controller (once we have node managers running under
      systemd). This will bring up/down node managers.
  * There will be a single job, called the cluster manager. The
    cluster manager can run on any host, but probably best to
    have it run on the host with the redis server.
  * It will essentially just run a set of process pools like the
    node manager.
  * The first process it will run will be the Distributor (see
    below).
  * Eventual goals:
    - It should be able to bring up/down node managers on each
      node through remote systemd through ssh.
